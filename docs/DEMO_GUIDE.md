# Как показать Credit Card Fraud Detection

Этот файл — инструкция для самостоятельной проверки приложения и демонстрации преподавателю.
Все команды выполняются из корня проекта.

## 1. Открыть приложение

Если Docker уже запущен, открой **http://localhost:8501**. После обновления приложения нажми
**Ctrl+F5**. На Mac можно обновить страницу через **Cmd+Shift+R**.

Если приложение не открывается:

```bash
docker compose up --build -d
```

Первый запуск скачивает данные и восстанавливает модель, поэтому нужно подождать несколько минут.
Посмотреть прогресс:

```bash
docker compose logs -f prepare
```

`Ctrl+C` завершает только просмотр логов. Проверить готовность:

```bash
docker compose ps --all
```

Нормальный результат: `prepare` завершился с кодом `0`, `app` имеет статус `healthy`.
Если ты изменил порт через `FRAUD_APP_PORT`, открывай соответствующий адрес, например
**http://localhost:8502**.

## 2. Самая простая демонстрация — готовая транзакция

1. В боковой панели выбери **Fraud Prediction**.
2. Открой вкладку **«Интерактивная демонстрация»**.
3. В списке **«Выберите транзакцию»** выбери **«Пример обычной покупки»**.
4. Нажми **«Вернуть исходную транзакцию»**, чтобы убрать правки от предыдущей попытки.
5. Нажми **«Проверить транзакцию»**.
6. Посмотри решение модели и строку **«Фактически в датасете»**. Приложение сообщает,
   совпал прогноз с известным классом или модель ошиблась.
7. Повтори шаги для **«Пример мошеннической операции»**.

В списке также есть два примера ошибок:

| Пример | Что произошло |
|---|---|
| Обычная покупка, на которой модель ошибается | Модель подняла ложную тревогу — false positive, FP |
| Мошенничество, которое модель пропускает | Модель пропустила мошенничество — false negative, FN |

Это реальные validation-примеры, специально подобранные для демонстрации четырёх исходов.
Они не являются случайной выборкой и не заменяют итоговую оценку качества на test.
Прогноз пересчитывается загруженной моделью, а не берётся из подписи примера.

## 3. Ввести свою сумму

1. Выбери готовую транзакцию — она задаёт исходный обезличенный профиль.
2. В поле **«Введите сумму покупки»** введи, например, `123.45` и нажми **Enter**.
3. Нажми **«Проверить транзакцию»**.
4. Раскрой **«Как модель приняла решение? Оценка и порог»**.
5. Сравни строки **«Исходная транзакция»** и **«Ваш сценарий»**.

Приложение использует введённую сумму вместе с остальными признаками выбранного примера.
Это не проверка произвольной покупки только по цене. Поле Amount работает в числовом масштабе
исходного датасета; приложение не выполняет конвертацию валют.

После изменения суммы фактический класс новой транзакции неизвестен. Нельзя утверждать,
что метка исходного примера автоматически относится к изменённой покупке.

**Почему решение может остаться прежним?** Сумма — только один из 29 входных признаков.
Модель учитывает весь набор. Кроме того, дерево решений реагирует на пересечение своих границ:
два разных значения суммы могут попасть в одну и ту же ветку. Даже если score изменился,
он может остаться по ту же сторону рабочего порога.

Чтобы снова проверить исходный пример, нажми **«Вернуть исходную транзакцию»**.
После изменения полей нужно повторно нажать кнопку проверки: старый результат скрывается.

### Свободный ввод — пятый вариант

В списке «Выберите транзакцию» после четырёх примеров выбери
**«Свободный ввод — своя транзакция»**. Введи Amount и любые значения V1–V28 в открытой форме,
подтверждая ввод Enter, затем нажми **«Проверить транзакцию»**.
Значения V вводятся с клавиатуры без ограничений диапазона ползунков. Отрицательные V допустимы,
сумма должна быть неотрицательной. Кнопка «Вернуть исходную транзакцию» сбрасывает свободный ввод в нули.
Это синтетический сценарий: истинный класс неизвестен. Нули не обозначают гарантированно обычную покупку.

## 4. Что такое V1–V28

**V1–V28 — входные признаки транзакции, а не гиперпараметры модели.**

В исходном наборе ULB эти столбцы представлены как обезличенные компоненты PCA.
PCA преобразует исходные признаки в числовые компоненты. Исходные названия полей и преобразование,
которое позволило бы восстановить конкретные банковские сведения, в проекте недоступны.

Поэтому нельзя назвать V1 «возрастом», V2 «страной», V3 «магазином» и так далее.
Каждая строка содержит 28 таких чисел и сумму Amount. По этим значениям модель учится отличать
транзакции с меткой `Class=1` от транзакций с меткой `Class=0`.

| Термин | Значение в нашем проекте |
|---|---|
| Признаки | Данные одной транзакции: V1–V28 и Amount |
| Целевая метка Class | Известный при обучении ответ: 1 — fraud, 0 — обычная операция |
| Time | Время от начала наблюдений; используется для разбиения и анализа, не передаётся модели |
| Гиперпараметры | Настройки обучения: например, число деревьев и максимальная глубина Random Forest |
| Порог | Граница, по которой оценка score превращается в итоговый класс |

В нашем приложении PCA заново не обучается: оно получает уже преобразованные V1–V28 из датасета.
Если вводить совершенно новую покупку из жизни, одной суммы недостаточно: для модели нужен
профиль в том же формате. Придумывать V-признакам бытовые названия было бы неверно.

## 5. Изменить V1 или V2 вручную

Для основной демонстрации этого делать не обязательно. Это технический эксперимент с поведением модели.

1. На вкладке **«Интерактивная демонстрация»** выбери пример.
2. Раскрой **«Технические признаки V1–V28 (необязательно)»**.
3. Измени ползунок **V1** или **V2**.
4. Нажми **«Проверить транзакцию»**.
5. В блоке **«Как модель приняла решение? Оценка и порог»** сравни исходную и изменённую строки.

Точные входные числа можно посмотреть в **«Посмотреть все входные данные»**, а затем скачать
кнопкой **«Скачать эту транзакцию CSV»**.

Изменение V1 не означает конкретное действие вроде смены страны покупки. Ты меняешь одну числовую
компоненту обезличенного профиля. Полученное сочетание признаков может не встречаться в реальных данных,
а его истинная метка неизвестна. Не нужно специально подбирать значения, чтобы любой ценой получить fraud.

## 6. Ввести все признаки таблицей

1. Перейди во вкладку **«Таблица признаков»** раздела Fraud Prediction.
2. Отредактируй значения в единственной строке. Для изменения ячейки дважды нажми на неё,
   введи число и подтверди Enter.
3. Сумма находится в столбце **Amount** после V28: при необходимости прокрути таблицу вправо.
4. Нажми **«Предсказать»**.

Стартовые нули — синтетическая заготовка, а не настоящая покупка. Для реалистичной демонстрации
удобнее выбрать готовый пример на первой вкладке. Если у тебя есть настоящая строка из датасета,
можно ввести все её признаки или загрузить CSV.

## 7. Загрузить CSV

Самый простой способ получить подходящий файл:

1. На вкладке **«Интерактивная демонстрация»** выбери пример.
2. Нажми **«Вернуть исходную транзакцию»**.
3. Скачай строку кнопкой **«Скачать эту транзакцию CSV»**.
4. Открой вкладку **«CSV-файл»** и загрузи скачанный файл.
5. Нажми **«Проверить и предсказать»**.
6. Убедись, что score и итоговый класс совпадают с прогнозом того же примера на первой вкладке.

Можно загрузить несколько транзакций. Нужны заголовки **V1–V28 и Amount**, числовые значения
без пропусков и разделитель-запятая. Поля `transaction_id` и `Class` необязательны.
Если есть Class, приложение дополнительно покажет исходы TP/TN/FP/FN. Class не используется
как входной признак модели. Результаты скачиваются кнопкой **«Скачать прогнозы CSV»**.

Кнопка **«Скачать шаблон CSV»** даёт только заголовки: перед предсказанием в шаблон нужно добавить строки.
Файл с колонками «магазин, страна, возраст» не подходит: модель не обучалась на такой схеме.

## 8. Как прочитать результат

- **FRAUD** — модель считает транзакцию подозрительной.
- **НЕ FRAUD** — модель отнесла транзакцию к обычным; это не гарантия отсутствия мошенничества.
- **Score** — оценка модели от 0 до 1. Не называй её гарантированной вероятностью мошенничества.
- **Порог ≈ 0.3452** — заранее выбранная на validation граница. Если `score >= threshold`, результат — fraud.
- **Фактический класс** — известная метка исходного примера, с которой можно сравнить прогноз.

Порог не равен 0.5 и при демонстрации не подбирается заново. Название модели — Random Forest с весами классов.

## 9. Что показать кроме отдельного предсказания

Проект отвечает на вопрос: **сколько мошенничества удаётся найти при ограничении числа ложных тревог?**

| Раздел | Что показать преподавателю |
|---|---|
| Data Overview | Разбиение данных, график дисбаланса, результат SQL-запроса |
| Model Comparison | Dummy baseline, Logistic Regression, Random Forest, стратегии балансировки и итоговый test |
| Error Analysis | Ложные тревоги, пропуски и важность признаков |
| Fraud Prediction | Работа модели на транзакции и изменение входных значений |

Сохранённый итог на test: обнаружено **39 из 52** мошеннических транзакций, **13 пропущено**,
есть **11 ложных тревог**. Precision — **78%**, recall — **75%**. Минимум precision 85% на test
**не достигнут** — это нужно сказать прямо. Смысл проекта в проверяемом сравнении методов,
а не в обещании безошибочного банковского сервиса.

## 10. Короткий текст для защиты

> Мы обучили модель находить мошеннические транзакции по сумме и 28 обезличенным признакам.
> Исходный смысл этих признаков не опубликован, поэтому для демонстрации используем готовые
> транзакции из датасета. Приложение передаёт признаки обученному конвейеру, получает оценку
> мошенничества и сравнивает её с порогом, выбранным на validation. Здесь видно решение модели
> и фактическую метку. Можно также изменить сумму или числовой профиль и посмотреть реакцию модели.
> На независимом test выбранная модель нашла 39 из 52 случаев, но целевой precision 85% не достигла.

Если спросят «V1–V28 — гиперпараметры?»:

> Нет. Это признаки конкретной транзакции. Гиперпараметры задают устройство модели — например,
> сколько деревьев в Random Forest. Входные признаки меняются от покупки к покупке,
> а настройки обученной модели во время демонстрации остаются фиксированными.

Если спросят «Почему нельзя проверить мою покупку по одной сумме?»:

> Наш датасет обезличен, а модель обучена на полном наборе признаков. Поэтому в этом приложении
> сумму можно менять внутри готового профиля. Для полноценного ввода страны, магазина и других
> понятных полей нужен другой датасет с такими сведениями и новое обучение.

## 11. Быстрая проверка перед показом

1. Открой обычный и мошеннический примеры, сбрасывая правки перед каждой исходной транзакцией.
2. Покажи один ошибочный пример и объясни разницу между ложной тревогой и пропуском.
3. Измени сумму, затем V1/V2; получи новый прогноз и посмотри текущие входные данные.
4. Скачай пример, загрузи его через CSV и сравни прогноз.
5. Открой Model Comparison и покажи test-результаты.
6. Запусти проверку:

```bash
docker compose exec -T app python -m src.evaluation.check --strict
```

Ожидается **17 OK, 0 WARN, 0 FAIL**. При красной надписи «ЗАГЛУШКА» это не настоящий прогноз:
для защиты должна быть загружена замороженная модель.

Источник описания полей: [ULB Credit Card Fraud Detection](https://www.kaggle.com/datasets/mlg-ulb/creditcardfraud).
Точный протокол и формат данных: [CONTRACTS.md](CONTRACTS.md).
